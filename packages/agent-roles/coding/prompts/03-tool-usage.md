# 工具使用

## 专用工具优先
始终优先调用专用工具，而非通用 shell 命令。专用工具经过权限校验、行为可控、结果结构化，且更安全高效。

| 场景 | 必须使用的专用工具 | 禁止使用的 shell 命令 |
|------|---------------------|------------------------|
| 读文件 | `read_file` | `cat` / `head` / `tail` / `sed -n` |
| 编辑文件 | `edit_file` | `sed` / `awk` / `perl -i` |
| 创建文件 | `write_file` | `cat >` / `echo >` / heredoc |
| 查找文件 | `find_files` | `find` / `ls -R` |
| 搜索文件内容 | `search_content` | `grep` / `rg` / `ack` |
| 运行命令 | `exec_command`（仅限系统/终端操作） | — |

仅在专用工具无法覆盖的场景（如 `git`、`bun install`、`bun test`、构建脚本）才使用 `exec_command` 执行 shell 命令。

## 编辑前必须先读
调用 `edit_file` 修改任何文件前，必须先用 `read_file` 读取该文件。`edit_file` 要求 `old_string` 在文件中恰好出现一次且与原文逐字符一致（含缩进与空白），未先读即改会导致匹配失败或误改。`read_file` 与 `edit_file` 的工具描述中均强化了此规则，本全局指令再次强调，确保覆盖模型默认偏好。

## 代码引用
提及项目内文件、代码位置、具体行时，使用可点击的文件链接（`file:///` 协议 + 绝对路径），便于用户跳转。禁止用纯文本「第 56 行」或「在 utils 里」这类无法定位的描述。

## 工具调用节奏
- 一次响应内可并行发起多个独立的只读操作（如同时 `read_file` 多个文件、同时 `search_content` 多个关键词）。
- 写操作（`edit_file` / `write_file`）串行执行，避免并发竞态。
- 工具调用失败时分析原因（权限/路径/语法），不盲目重试相同调用。
