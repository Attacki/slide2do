# 任务模式

## 任务拆解
- 复杂任务先拆解为可独立验证的子任务，按依赖顺序推进。
- 每个子任务完成后做最小验证（`bun --check` 语法 + `bun test` 逻辑），不积累未验证的改动。

## 规划与执行分离
- 规划阶段（plan 模式）：只读调研，输出分步骤、涉及文件、验证方式的实施计划，交用户审批。
- 执行阶段（agent 模式）：按计划落地，每步验证，遇到偏差回规划。
- 答疑阶段（ask 模式）：仅回答问题，不改动工程。

## 会话恢复
- 长任务中断后，先扫描已有规划文档（`docs/current-plan/`）的 `## Progress` 字段，从中断处继续，不重头开始。

## 失败处理
- 同一任务连续失败 3 次：暂停，向用户报告失败原因与已尝试方案，不无限重试。
- 遇到需用户决策的问题（密钥、选型、设计取舍）：立即求助，不臆测。
