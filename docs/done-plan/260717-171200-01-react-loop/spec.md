# spec.md — ReAct 循环引擎

## 背景
当前核心引擎的 `BaseAgent.processInput` 只做「单次 LLM 调用 + 单次工具执行后即停止」，模型看不到工具结果、无法基于结果继续推理。这与真正可用的 ReAct 智能体形态存在根本差距：缺少把工具结果回灌模型并持续多轮推理的「循环本体」。本章补上这一核心能力，并以事件流对外暴露全过程、以状态机管控终止、以分组策略安全执行工具。

## 目标用户
- 使用 wuzi-agent 的终端 / CLI 终端用户。
- 上层 UI（TUI / CLI）开发者：需要可观测、可取消、可切换规划模式的循环过程来消费渲染。

## 核心能力清单
- 一轮 = 调 LLM → 拿响应 → 有工具调用就执行 → 结果回填 → 下一轮；无工具调用即结束（ReAct 范式）。
- 对外以事件流暴露全过程（用户消息、模型思考、模型文本、工具调用开始、工具结果、最终回复、循环终止、错误），上层按需消费。
- 每轮结束以状态机判断「继续 / 终止」，终止情形：模型显式 end_turn、无工具调用、达到最大轮数、用户取消、超时。
- 一轮内多个工具调用按读类（安全，可并发）/ 写类（互斥，串行）分组执行。
- 提供 plan-only 开关（启动配置 + 运行时可切换），开启后仅允许读类工具，写类工具被拦截并提示关闭开关，最终输出计划交审批。
- 支持外部取消（AbortSignal）与内置超时双通道，中途打断状态保持一致、不抛未捕获异常。

## 非功能要求
- 循环本体与展示层解耦，仅通过 `StreamEvent` 通信，UI 可替换不动核心。
- 工具执行复用现有 `ToolExecutor`（含单工具超时与结构化错误），循环内不重复实现超时逻辑。
- 可观测：每一轮、每个工具调用、每种终止原因都有对应事件，便于排障与渲染。
- 可测试：循环状态机、工具分组、plan-only 拦截均为纯函数 / 可 Mock，不依赖真实 LLM 与网络。

## 设计骨架
- `@wuzi/types`：在 `Tool` / `ToolDefinition` 增加「是否产生副作用」标记，供分组判断。
- `@wuzi/core/ui-pattern.ts`：扩展 `StreamEvent`（用户消息、工具调用开始、最终回复、plan 拦截、循环终止等）与 `CommandEvent`（新增 `/plan` 运行时切换命令）。
- `@wuzi/core` 新增 react-loop 编排模块：持有 provider / 记忆 / 注册中心 / 执行器，驱动多轮；内部实现分组执行、plan-only 拦截、双通道取消与终止状态机。
- `@wuzi/core/base-agent.ts`：单轮逻辑下沉为可复用步骤，`processInput` 委托给 react-loop 编排模块。
- `@wuzi/core/agent-loop.ts`：持有取消信号（`AbortController`），`/exit` 与 `stop` 触发 abort，并透传循环配置与运行时 `/plan` 切换。
- `@wuzi/types` 配置层：新增循环配置（最大轮数、plan-only、超时）。
- `app/`：装配循环配置与取消信号，打通端到端。

## Out of Scope（本章不做）
- 复杂 system prompt 组装：本章用最小可用 system prompt 跑起来即可。
- 完整权限策略：本章仅在工具执行前留拦截位（plan-only 写类拦截），不实现具体权限规则与交互询问（权限三选项系统留待后续章节）。
- 工具调用间的跨工具结果依赖编排（DAG）：仅按读 / 写分组，不做依赖图分析。

## 版本完成标准
- 多轮 ReAct 循环可端到端跑通：模型能基于前一轮工具结果继续推理直至结束。
- 事件流完整覆盖用户消息 / 思考 / 文本 / 工具调用开始 / 工具结果 / 最终回复 / 循环终止 / 错误。
- 读类工具并发、写类工具串行，行为与顺序可验证。
- plan-only 下写类工具被拦截并提示关闭开关，最终输出计划文本。
- 外部取消与内置超时任一触发都能干净终止，状态一致、无未捕获异常。
- 全部单元测试与端到端验收项通过。
